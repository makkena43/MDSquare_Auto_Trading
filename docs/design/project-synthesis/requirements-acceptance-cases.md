# Requirements acceptance cases

Version 0.10.0. These are original hypothetical requirement scenarios, not market observations, runnable tests or passed evaluations. Each case is evaluated using only the stated cutoff evidence. Expected behavior is a review rubric; no unseen candle or profitable outcome is supplied. For a complete CANDIDATE, numerical data, switches and policy must additionally satisfy the decision contract.

## Review recording

For each case record input cutoff/source availability, supplied policy, model/skill version, interpretation, governing evidence, unresolved issues and reviewer disagreement. Mark NOT_RUN, CONSISTENT, INCONSISTENT or INCONCLUSIVE. These cases are currently NOT_RUN as independent evaluations. A format/link check does not change that status.

Judge separately: context/ancestry agreement; opposition judgment; plan consistency; management reasoning; identity/availability requirements. Economic results and execution latency are separate streams. For disagreements, retain both interpretations and the required discriminator; do not settle by looking at later P&L.
